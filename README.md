# Obsidian Telegram Bot

Telegram-бот на языке Go для работы с удалённым хранилищем **Obsidian Vault** непосредственно из Telegram.

Хранилище размещается в удалённом GitHub-репозитории. Доступ к репозиторию осуществляется через GitHub OAuth, что позволяет создавать заметки с использованием заранее настроенных алиасов путей и шаблонов.

## Сценарий использования: быстрое добавление задачи в Obsidian

Типичная ситуация: пользователь находится вне дома и вспоминает о задаче, которую необходимо выполнить, при этом прямого доступа к хранилищу у пользователя нет.

Обычно в таком случае задачу приходится сохранять в заметках телефона, а затем вручную переносить в Obsidian. Это создаёт лишний шаг и повышает вероятность того, что задача останется неперенесённой.

С помощью бота задачу можно добавить в Obsidian сразу из Telegram:

1. Открыть чат с ботом.
2. Вызвать команду `/add_note`.
3. Выбрать нужный алиас, например `tasks`.
4. Выбрать шаблон задачи.
5. Ввести необходимые данные.
6. Бот создаст Markdown-файл в нужной директории Obsidian Vault.
7. Изменения будут сохранены в GitHub-репозитории.

В результате задача оказывается в том же Obsidian-хранилище, с которым пользователь работает на компьютере, без промежуточного сохранения в другом месте и последующего ручного переноса.

## Возможности

Бот поддерживает следующие команды:

| Команда           | Описание                                                          |
| ----------------- | ----------------------------------------------------------------- |
| `/start`          | Вывести список доступных команд                                   |
| `/menu`           | Вывести список доступных команд                                   |
| `/connect_github` | Подключить Telegram-чат к GitHub-аккаунту                         |
| `/set_repo`       | Установить GitHub-репозиторий, в котором находится Obsidian Vault |
| `/alias`          | Показать существующие алиасы путей                                |
| `/template`       | Показать существующие шаблоны                                     |
| `/add_alias`      | Создать новый алиас пути                                          |
| `/add_template`   | Создать новый текстовый шаблон                                    |
| `/add_note`       | Создать новую заметку                                             |

### Алиасы

Алиасы позволяют не указывать длинные пути к директориям и файлам при каждом создании или обновлении заметки.

Например, вместо:

```text
Projects/Personal/Tasks/2026/
```

можно создать алиас:

```text
tasks
```

После этого при работе с заметками достаточно использовать `tasks`.

### Шаблоны

Шаблоны позволяют заранее определить структуру текста, добавляемого в заметку.

Это удобно, когда заметка должна содержать только несколько определённых полей. Бот принимает необходимые данные, подставляет их в шаблон и формирует итоговое содержимое заметки.

### Создание заметок

Команда `/add_note` использует настроенные алиасы и шаблоны, создаёт заметку в нужном месте Obsidian Vault и сохраняет изменения в GitHub-репозитории.

Таким образом, после отправки команды изменения оказываются непосредственно в удалённом хранилище.

## Принцип работы

Упрощённо взаимодействие компонентов выглядит следующим образом:

```text
Telegram
   │
   ▼
Telegram Bot
   │
   ├── GitHub OAuth ──► GitHub Account
   │
   ▼
GitHub Repository (содержит Obsidian Vault)
```

Telegram выступает в роли пользовательского интерфейса, а GitHub — в роли удалённого хранилища Obsidian Vault.

Для каждого Telegram-чата можно подключить GitHub-аккаунт и выбрать репозиторий, содержащий Vault.

## Требования

Для запуска проекта необходимы:

* Компилятор Go.
* Сервер PostgreSQL.
* Telegram-бот, созданный через BotFather.
* GitHub OAuth App.
* Публичный HTTPS-доступ (домен или IP-адрес с возможностью выпуска TLS-сертификата).
* TLS-сертификат и приватный ключ.

Публичный HTTPS-сервер требуется для двух целей:

1. GitHub OAuth callback — GitHub должен иметь возможность перенаправить пользователя обратно в приложение после авторизации.
2. Telegram webhook — Telegram должен иметь возможность доставлять обновления на сервер бота.

## Создание Telegram-бота

Создайте бота через [@BotFather](https://t.me/BotFather) и получите его token.

Token не указывается напрямую в конфигурационном файле: он загружается из секрета `tg_token` (см. раздел «Хранение секретов»). В конфигурации за это отвечает параметр `telegram.token`, который при запуске перезаписывается значением из файла секрета.

## Создание GitHub OAuth App

В GitHub создайте OAuth App и получите:

* Client ID;
* Client Secret.

В качестве `Authorization callback URL` необходимо указать URL, по которому приложение принимает ответ GitHub после авторизации. Фактический путь обработчика — `/callback`.

Например:

```text
https://example.com/callback
```

Client ID и Client Secret загружаются из секретов `github_id` и `github_secret` (см. раздел «Хранение секретов») и перезаписывают соответствующие поля конфигурации `github.client_id` и `github.client_secret`.

Эти значения указываются в конфигурации:

```yaml
github:
  client_id: ""          # перезаписывается секретом github_id
  client_secret: ""      # перезаписывается секретом github_secret
  redirect_url: "https://example.com/callback"
  scopes: "repo"
```

Секреты (`client_secret` и Telegram token) не должны публиковаться в Git-репозитории.

## PostgreSQL

Боту необходим PostgreSQL для хранения данных приложения.

Создайте базу данных и пользователя, например:

```sql
CREATE DATABASE obsidian_bot;
CREATE USER obsidian_bot WITH PASSWORD 'password';
GRANT ALL PRIVILEGES ON DATABASE obsidian_bot TO obsidian_bot;
```

Пароль пользователя базы данных загружается из секрета `db_pass` (см. раздел «Хранение секретов») и перезаписывает поле `db.password` из конфигурации.

Схема базы данных создаётся SQL-скриптом инициализации, поставляемым с проектом. В репозитории он располагается по пути `sql/init.sql`. Путь к этому файлу и параметры подключения указываются в конфигурации.

## Конфигурация

Путь к конфигурационному файлу передаётся через переменную окружения `CONFIG_PATH`.

Пример:

```bash
export CONFIG_PATH=/path/to/config.yaml
```

Пример конфигурационного файла:

```yaml
db:
  host: "127.0.0.1"
  port: 5432
  user: "obsidian_bot"
  password: ""           # перезаписывается секретом db_pass
  name: "obsidian_bot"
  init_sql_filepath: "./sql/init.sql"

telegram:
  webhook_url: "https://example.com/telegram/webhook"
  webhook_endpoint: "/telegram/webhook"
  token: ""              # перезаписывается секретом tg_token

github:
  client_id: ""          # перезаписывается секретом github_id
  client_secret: ""      # перезаписывается секретом github_secret
  redirect_url: "https://example.com/callback"
  scopes: "repo"

server:
  addr: ":8443"

tls:
  cert_file: "/path/to/fullchain.pem"
  key_file: "/path/to/privkey.pem"

secrets_dir: "./secret"
```

### Описание параметров

#### `db`

Параметры подключения к PostgreSQL:

* `host` — адрес PostgreSQL-сервера;
* `port` — порт PostgreSQL;
* `user` — пользователь базы данных;
* `password` — пароль пользователя (перезаписывается секретом `db_pass`);
* `name` — название базы данных;
* `init_sql_filepath` — путь к SQL-файлу инициализации схемы (`sql/init.sql`).

#### `telegram`

Настройки Telegram:

* `webhook_url` — полный публичный HTTPS-URL, по которому Telegram доставляет обновления (включая путь);
* `webhook_endpoint` — локальный путь, на котором приложение принимает webhook-запросы;
* `token` — token Telegram-бота (перезаписывается секретом `tg_token`).

#### `github`

Настройки GitHub OAuth:

* `client_id` — Client ID GitHub OAuth App (перезаписывается секретом `github_id`);
* `client_secret` — Client Secret GitHub OAuth App (перезаписывается секретом `github_secret`);
* `redirect_url` — OAuth callback URL (фактический путь обработчика — `/callback`);
* `scopes` — OAuth-права, запрашиваемые приложением.

#### `server`

Настройки HTTP/HTTPS-сервера:

* `addr` — адрес и порт, на котором запускается сервер.

Пример:

```yaml
server:
  addr: ":8443"
```

#### `tls`

Параметры TLS-сертификата:

* `cert_file` — путь к сертификату;
* `key_file` — путь к приватному ключу.

Пример:

```yaml
tls:
  cert_file: "/etc/letsencrypt/live/example.com/fullchain.pem"
  key_file: "/etc/letsencrypt/live/example.com/privkey.pem"
```

#### `secrets_dir`

Директория с файлами секретов. Из неё при запуске считываются файлы `db_pass`, `tg_token`, `github_id` и `github_secret`, значения которых подставляются в соответствующие параметры конфигурации. Если переменная окружения `SECRETS_DIR` задана, она имеет приоритет над `secrets_dir`.

## Хранение секретов

Чувствительные данные (Telegram Bot Token, GitHub Client ID и Client Secret, пароль PostgreSQL) не хранятся в конфигурационном файле. При запуске они считываются из отдельных файлов в директории, заданной параметром `secrets_dir` (или переменной окружения `SECRETS_DIR`). Каждый секрет размещается в файле с соответствующим именем:

| Секрет            | Параметр конфигурации              |
| ----------------- | ---------------------------------- |
| `tg_token`        | `telegram.token`                   |
| `github_id`       | `github.client_id`                 |
| `github_secret`   | `github.client_secret`             |
| `db_pass`         | `db.password`                      |

Конфигурационные файлы и директорию секретов следует исключить из версионного контроля.

## Запуск локально

### 1. Клонирование репозитория

```bash
git clone <REPOSITORY_URL>
cd <PROJECT_DIRECTORY>
```

### 2. Установка зависимостей

```bash
go mod download
```

### 3. Создание конфигурации

Создайте YAML-файл, например:

```text
config/local.yaml
```

и заполните его необходимыми параметрами согласно разделу «Конфигурация».

### 4. Подготовка секретов

Создайте директорию для секретов (например, `secret/`) и поместите в неё файлы `tg_token`, `github_id`, `github_secret` и `db_pass` с соответствующими значениями. Укажите путь к этой директории в `secrets_dir` конфигурации либо через переменную окружения `SECRETS_DIR`.

### 5. Установка `CONFIG_PATH`

Linux/macOS:

```bash
export CONFIG_PATH=$(pwd)/config/local.yaml
```

Проверить значение:

```bash
echo $CONFIG_PATH
```

### 6. Запуск PostgreSQL

Убедитесь, что PostgreSQL запущен и база данных из конфигурации существует. Скрипт инициализации схемы (`sql/init.sql`) применяется автоматически при запуске приложения.

### 7. Запуск приложения

```bash
go run ./cmd
```

Также возможен запуск через Docker Compose, если он используется в проекте.

## HTTPS и Telegram Webhook

Для полноценной работы бота сервер должен быть доступен из интернета по HTTPS.

Telegram должен иметь возможность доставлять webhook-запросы по URL, указанному в `telegram.webhook_url`, например:

```text
https://example.com/telegram/webhook
```

TLS-сертификат и приватный ключ передаются приложению через параметры `tls.cert_file` и `tls.key_file`.

Если приложение запускается на компьютере, недоступном из интернета, Telegram webhook и GitHub OAuth callback не будут работать без дополнительного публичного туннеля или внешнего сервера.

## GitHub OAuth

После запуска пользователь может выполнить команду:

```text
/connect_github
```

Бот направит пользователя на GitHub для авторизации. После успешной авторизации GitHub перенаправит пользователя на `redirect_url` (фактический путь — `/callback`), после чего бот сможет использовать полученные права для работы с репозиториями пользователя.

Затем можно выбрать репозиторий с Obsidian Vault:

```text
/set_repo
```

После настройки GitHub и репозитория становятся доступны операции с заметками.

## Пример сценария использования

Предположим, пользователь находится вне дома и вспомнил о задаче, которую необходимо выполнить.

Вместо сохранения задачи в отдельные заметки телефона он открывает Telegram и взаимодействует с ботом:

```text
/add_note
```

Выбирает заранее настроенный алиас:

```text

```

Выбирает шаблон:

```text
task
```

Бот создаёт соответствующую Markdown-заметку в Obsidian Vault и сохраняет изменения в GitHub.

Когда пользователь возвращается к компьютеру и синхронизирует Vault, задача уже находится в Obsidian.

## Безопасность

Конфигурация и окружение содержат чувствительные данные, в частности:

* Telegram Bot Token;
* GitHub OAuth Client Secret;
* пароль PostgreSQL;
* приватный TLS-ключ.

Не добавляйте конфигурационные файлы с реальными значениями и файлы секретов в Git.

Для локальной разработки рекомендуется использовать отдельные конфигурационный файл и директорию секретов, исключённые из версионного контроля. Актуальное содержимое `.gitignore` в репозитории:

```gitignore
config/*
secret/*
*.out
```
